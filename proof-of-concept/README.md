# Proof of concept — what the two final deliverables look like when finished

Status: example — 2026-10-24 (session 3: R-02, R-03, scene export, portfolio page, render prompts)

This folder holds one worked example of each final deliverable named in `AGENTS.md`: a floor plan sheet and a rendered exterior perspective. It exists so that a student (or a session) can see the format and level of finish the package is working towards before any of the real design exists.

**Nothing in this folder is the project.** The geometry, areas, viewpoint, materials, and sun angle were invented for the example. They resolve no open question, close no gate, and are not a massing option. Do not read a number from here into any other file; the owning files in the `AGENTS.md` table remain the only source. The real deliverables will be produced in Phase 5 of `PHASE_PLAN.md` and will live in `assets/drawings/` and `assets/renders/`, not here.

## How to use it when reviewing a real deliverable

Hold the real sheet next to the example and check the same things the example shows: every item in the drawing-list row for that sheet in `05-architecture/drawing-list.md`, the drawing conventions in `STANDARDS.md`, and for the render the content checklist in `05-architecture/rendered-perspective.md`. The example is a floor, not a ceiling: a real A-101 at the final gate will also carry the DB-SI sector references, accessible-route notes and reconciled areas that the example only gestures at in its general notes.

Two deliberate limits of the example, so no one mistakes them for the target:

- The plan shows a ground floor only and stubs the guestroom wing with a break line. The real package needs every distinct level (A-101 to A-104 in the drawing list) and the plan takeoff must reconcile to `03-program/area-schedule.csv`.
- The renders are flat-shaded procedural images, not physically based renderings from a modelling pipeline. They demonstrate composition, viewpoint logic, light, and captioning. The real R-01 should come from the modelling and rendering route recorded under "Production" in `05-architecture/rendered-perspective.md`, and must show only elements that exist in the floor plans.

## Regenerating

Both scripts run on Python 3 with `matplotlib`, `numpy` and `Pillow`, and take the output path without extension as the single argument. Run them from the repository root:

```
python proof-of-concept/generators/make_plan.py proof-of-concept/A-101-planta-baja-ejemplo
python proof-of-concept/generators/make_render.py proof-of-concept/R-01-perspectiva-ejemplo R-01
python proof-of-concept/generators/make_render.py proof-of-concept/R-02-perspectiva-ejemplo R-02
python proof-of-concept/generators/make_render.py proof-of-concept/R-03-perspectiva-ejemplo R-03
python proof-of-concept/generators/make_render.py proof-of-concept/scene scene
```

The last line regenerates `scene.js` for `portfolio.html`; run it whenever the scheme in `make_render.py` changes, so the model and the stills do not drift apart.

`make_plan.py` keeps the example scheme as a list of rooms in metres; areas on the sheet are computed from that list, so a change to a room changes its label. The sheet is A0 at 1:100, so the plan must fit about 114 m × 56 m; the script's origin constants are what to move if it does not. `make_render.py` builds the same scheme as boxes, projects it through a pinhole camera, sorts by depth, and shades with one sun. The `VIEWS` table at the top holds one entry per still (camera, sun azimuth and elevation in plan-maths degrees, sky, fog, season, caption) and the `SEASONS` table holds the canopy parameters; the scheme itself follows and is shared by every view and by the scene export. Feedback on either example should be applied to the script and the outputs regenerated, so the example and its source never drift apart.
